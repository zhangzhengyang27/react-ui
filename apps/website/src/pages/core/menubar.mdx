## 用法

`Menubar` 是桌面应用风格的菜单栏：一排顶级菜单触发器（File、Edit、View…），每个触发器都会打开一个下拉菜单。方向键可以在顶级菜单之间移动，一旦某个菜单打开，移动到同级菜单会立即打开它。`Menubar` 遵循 [WAI-ARIA menubar 模式](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/)。

`Menubar` 基于 [Menu](/core/menu) 构建——每个 `Menubar.Menu` 都是一个独立的 `Menu` 实例，下拉内容由常用的 `Menu.Item`、`Menu.Divider`、`Menu.Label`、`Menu.Sub`、`Menu.CheckboxItem` 和 `Menu.RadioItem` 组件组合而成。

## 与 Menu 的区别

[Menu](/core/menu) 是一个单独的披露控件——一个目标元素切换一个下拉菜单。`Menubar` 则协调多个菜单：

- 根元素渲染 `role="menubar"`，`Menubar.Target` 渲染 `role="menuitem"` 触发器，并带有 `aria-haspopup="menu"`。
- 菜单栏中同一时间只有一个菜单处于打开状态。当某个菜单打开时，悬停到同级目标会切换到对应的菜单。
- 整个菜单栏是一个 tab 停靠点（roving `tabindex`）——按 `Tab` 键将焦点作为一个整体移入或移出菜单栏，方向键在触发器之间移动焦点。

如果你只需要一个按钮附加单个下拉菜单，请改用 [Menu](/core/menu)。

## 组合

`Menubar` 由以下组件组成：

- `Menubar` – 根元素，管理所有菜单的打开/活动状态
- `Menubar.Menu` – 包裹单个菜单，内部渲染一个 `Menu` 实例
- `Menubar.Target` – 顶级触发按钮（`role="menuitem"`）
- `Menubar.Dropdown` – 下拉容器，接受的子元素与 `Menu.Dropdown` 相同

```tsx
import { Menu, Menubar } from '@react-ui/ui';

function Demo() {
  return (
    <Menubar>
      <Menubar.Menu>
        <Menubar.Target>文件</Menubar.Target>
        <Menubar.Dropdown>
          <Menu.Item>新建文件</Menu.Item>
          <Menu.Item>Open…</Menu.Item>
        </Menubar.Dropdown>
      </Menubar.Menu>

      <Menubar.Menu>
        <Menubar.Target>编辑</Menubar.Target>
        <Menubar.Dropdown>
          <Menu.Item>撤销</Menu.Item>
          <Menu.Item>重做</Menu.Item>
        </Menubar.Dropdown>
      </Menubar.Menu>
    </Menubar>
  );
}
```

## 触发与循环

`trigger` 控制当前没有任何菜单打开时如何打开菜单：

- `click`（默认）—— 点击目标时打开菜单。一旦任意菜单打开，悬停到同级目标会立即切换。这与原生桌面应用菜单栏行为一致。
- `hover` – 只要悬停到目标就会打开菜单，即使所有菜单都关闭。

使用 `trigger="hover"` 时，悬停目标会立即打开菜单，指针离开菜单栏时关闭：

<Demo data={MenubarDemos.hover} />

`loop`（默认 `true`）控制使用方向键导航时，是否从最后一个菜单绕回到第一个菜单，反之亦然。

## 子菜单

在 `Menubar.Dropdown` 内使用 `Menu.Sub` 创建嵌套子菜单。`ArrowRight` 打开子菜单并将焦点移到第一项，`ArrowLeft` 关闭子菜单并将焦点返回父项。更多信息请参阅 [Menu 子菜单文档](/core/menu/#submenus)。

上方的[用法示例](#用法)在 File 菜单中包含了子菜单。

## 复选框与单选项

`Menubar.Dropdown` 支持与 `Menu` 相同的选择项：`Menu.CheckboxItem` 用于切换选项，`Menu.RadioGroup` 配合 `Menu.RadioItem` 用于单选。默认情况下，点击复选框或单选项不会关闭菜单。

## 受控模式

设置 `openIndex` 和 `onOpenChange` 来控制哪个菜单处于打开状态。`openIndex` 是打开的 `Menubar.Menu` 的零基索引（按 DOM 顺序），当所有菜单都关闭时为 `null`：

<Demo data={MenubarDemos.controlled} />

对于非受控用法并希望初始有一个菜单打开，请改用 `defaultOpenIndex` 属性。

## 位置

默认情况下，下拉菜单相对于目标定位在 `bottom-start`。更改 `position` 属性可为菜单栏中的所有菜单使用不同的 [Floating UI 位置](/core/popover/#position-and-placement)：

```tsx
import { Menubar } from '@react-ui/ui';

function Demo() {
  return (
    <Menubar position="bottom-end">
      {/* ...menus */}
    </Menubar>
  );
}
```

单个菜单接受与 [Menu](/core/menu) 相同的属性——将它们传给 `Menubar.Menu` 以覆盖单个菜单的设置，例如 `position`、`withinPortal`、`closeOnItemClick`、`shadow`、`width` 或 `transitionProps`。

## 可访问性

`Menubar` 遵循 [WAI-ARIA menubar 模式](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/)：

- 根元素具有 `role="menubar"` 和 `aria-orientation="horizontal"`。
- 每个 `Menubar.Target` 具有 `role="menuitem"`、`aria-haspopup="menu"` 和 `aria-expanded`。
- 菜单栏是单个 tab 停靠点——只有活动触发器包含在 tab 顺序中，方向键在触发器之间移动焦点。

传给 `Menubar.Target` 的文本将作为触发器的可访问名称，因此请确保它们能描述菜单内容。
